## 6. What to do with this

1. Work from section 3, not section 2. A map you lose is a symptom; the behaviour
   that loses it is the cause. Prefer a behaviour that appears on many maps.
2. For each behaviour you address, state explicitly whether it is a **bug** (the
   bot did something it did not intend), a **policy problem** (it did what it
   intended and that was wrong), or **working as designed**.
3. Propose the smallest change that fixes the cause, and name the behaviour and
   map it should resolve.
4. Say how it should be measured. In this game the engine is non-deterministic
   and there is a real side advantage, so the only meaningful comparison is a
   paired, colour-swapped run over the whole map pool with enough seeds that the
   confidence interval excludes 50%. A single match proves nothing.
5. Do not tune a numeric parameter to fix a structural bug. Parameters tuned
   against a broken behaviour reverse sign once the behaviour is fixed.
